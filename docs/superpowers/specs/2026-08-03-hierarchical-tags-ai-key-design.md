# 多级标签、层级筛选与后端 AI Key 设计

## 目标

修复文章列表标签筛选，支持任意层级标签；标签管理页仅以顶级标签作为入口并可展开管理子标签；智谱 API Key 仅从后端环境变量读取。

## 已确认行为

- 标签采用 `parent_id` 自关联邻接表，`NULL` 表示顶级标签。
- 点击任意标签筛选文章时，匹配该标签及其全部后代标签。
- 标签列表接口返回平铺数据和 `parent_id`，前端构建树，避免新增重复接口。
- 父标签存在子标签时拒绝删除，避免隐式级联误删。
- 更新父级时拒绝自身作为父级及形成祖先循环。
- 前端删除 API Key 输入和请求字段；模型选择与是否启用 AI 保留。
- 后端使用 `ZHIPU_API_KEY`；缺失时仅在启用 AI 导入时明确报错并记录日志。

## 数据库

为 `tags` 增加可空 `parent_id`、索引和指向 `tags.id` 的外键，删除规则为 `RESTRICT`。既提供 Aerich 迁移，也提供 MySQL 手工 SQL 脚本；现有标签迁移后均为顶级标签。

## 验证

- 后端测试：后代集合、父子创建/更新、循环拒绝、父标签筛选、环境变量 Key、请求不再接受 API Key。
- 前端测试：组合查询参数；树构建只返回顶级入口且保留任意深度。
- 构建与启动：后端导入/健康检查、前端测试和 `npm run build`。
